# 14 Свойства зависимостей события и привязка данных

**Связь с программой:** тема 2.2, строка 4, 2 часа. Подготовка к ПР 7 и 10.

**Цель:** понять механизм связи интерфейса с данными и маршрутизацию событий.

**Результат:** студент называет цель, свойство цели, источник и путь привязки, выбирает режим.

**Нужно знать:** свойства, события, дерево WPF.

**Обязательная часть:** dependency property, routed event, `DataContext`, `Binding`, режимы, уведомления. **Дополнительно:** attached property.

## Лекция

Свойство зависимостей — свойство WPF, значение которого может приходить из локальной установки, стиля, привязки, анимации или наследования. Система определяет итоговое значение по правилам приоритета. Поэтому `TextBox.Text` способен участвовать в привязке, а обычное поле C# — нет как свойство цели.

Маршрутизируемое событие проходит по дереву. Tunneling-событие с префиксом `Preview` идёт от корня к источнику, bubbling — от источника вверх. Родитель может обработать событие дочернего элемента. Свойство `Handled` сообщает, что событие обработано, но некоторые обработчики могут быть настроены на уже обработанные события.

Привязка состоит из четырёх частей: объект-цель, свойство цели, источник и путь. В `Text="{Binding Name}"` цель — `TextBox`, свойство — `Text`, источник обычно берётся из `DataContext`, путь — `Name`.

`OneWay` переносит изменения источника в интерфейс. `TwoWay` добавляет обратное обновление. `OneTime` читает один раз. `OneWayToSource` нужен реже. Режим выбирают по задаче: текст для чтения — `OneWay`, поле редактирования — обычно `TwoWay`.

Источник должен уведомлять об изменениях. Объект реализует `INotifyPropertyChanged`, коллекция — `ObservableCollection<T>`. Обычный `List<T>` не сообщает интерфейсу о добавлении. `DataContext` наследуется вниз по дереву; случайная замена контекста на дочернем элементе объясняет многие «пустые» привязки.

```xml
<TextBox Text="{Binding Name,
                        Mode=TwoWay,
                        UpdateSourceTrigger=PropertyChanged}" />
```

`UpdateSourceTrigger=PropertyChanged` обновляет источник при каждом изменении текста, что удобно для немедленной проверки, но может запускать тяжёлую работу слишком часто. Ошибки привязки обычно не останавливают приложение; их нужно искать в окне Output.
