# 18 База данных, ER-модель и модель по существующей БД

**Связь с программой:** тема 2.2, строка 8, 2 часа. Подготовка к ПР 12.

**Цель:** перейти от предметных понятий к связанной модели данных и понять роль ORM.

**Результат:** студент выделяет сущности, ключи и связи, читает схему и объясняет отображение строк БД на объекты.

**Нужно знать:** классы, коллекции, ограничения. **Обязательная часть:** таблица, строка, столбец, первичный/внешний ключ, кардинальность, ER/EDM, ORM, EF Core. **Дополнительно:** миграции.

## Лекция

Реляционная база хранит данные в таблицах. Строка описывает один экземпляр, столбец — один атрибут. Первичный ключ устойчиво различает строки. Внешний ключ связывает строку с другой таблицей и не позволяет ссылаться на несуществующий объект, если включена ссылочная целостность.

В предметной области курса есть `Project` и `TaskItem`: у одного проекта много задач, каждая задача относится к одному проекту. Это связь «один ко многим».

```text
Project 1 ───────< TaskItem
id PK              id PK
name               project_id FK → Project.id
                   title
                   is_done
```

ER-модель показывает сущности, атрибуты и связи. EDM в классическом .NET обозначала концептуальную модель данных и отображение на хранилище. Современный учебный путь использует EF Core: классы становятся сущностями, `DbContext` — единицей работы с БД, а LINQ-запрос переводится в SQL. Это современная реализация идеи отображения, но не тот же визуальный дизайнер EDM из старого Entity Framework.

Есть два направления. Database First начинает с существующей схемы и генерирует классы командой scaffolding. Code First начинает с классов и строит схему миграциями. В ПР 12.1 дана существующая SQLite-база и схема; студент сначала понимает таблицы, затем получает/сверяет модель.

ORM не отменяет SQL. Разработчик должен понимать ключи, ограничения, количество запросов и границы транзакции. Небрежная загрузка связанных данных может породить множество запросов. Изменение объекта в памяти не обязательно сохранено: требуется `SaveChanges`/`SaveChangesAsync`.

Ошибки: имя считают ключом; внешний ключ допускает «осиротевшую» запись; удаление родителя не спроектировано; типы допускают `null` без смысла; изменения объекта принимают за сохранённые; файл БД ищут в неожиданной рабочей папке.
