# 15 Преобразование и проверка данных

**Связь с программой:** тема 2.2, строка 5, 2 часа. Подготовка к ПР 8–10.

**Цель:** отличать преобразование представления от проверки допустимости данных.

**Результат:** студент выбирает конвертер или правило проверки, формулирует сообщение и граничные случаи.

**Нужно знать:** привязка, типы, предметные ограничения.

**Обязательная часть:** `IValueConverter`, форматирование, `ValidationRule`, `IDataErrorInfo`/`INotifyDataErrorInfo`, границы. **Дополнительно:** культура.

## Лекция

Данные модели и вид на экране могут иметь разные формы. Логическое `true` можно показать словом «Завершён», дату — локальной строкой, цвет — кистью. Преобразователь `IValueConverter` меняет представление для привязки. Он не должен сохранять данные или выполнять сетевой запрос.

Проверка отвечает другому вопросу: допустимо ли значение. Проверяют формат, обязательность, диапазон и предметные правила. Формат «12» для часов корректен, но значение `-1` недопустимо. Название может быть строкой, но пустая строка нарушает правило.

```csharp
public string? ValidateHours(string text)
{
    if (!int.TryParse(text, out int hours))
        return "Введите целое число";
    if (hours is < 0 or > 1000)
        return "Часы должны быть от 0 до 1000";
    return null;
}
```

WPF позволяет проверять на уровне `ValidationRule` в привязке или сообщать ошибки из модели/ViewModel через `IDataErrorInfo` и `INotifyDataErrorInfo`. Для правил, зависящих от нескольких полей и асинхронных проверок, удобнее ViewModel. В учебном проекте выбран простой синхронный путь и одно место истины.

Сообщение должно объяснять, что исправить: «Введите дату в формате ДД.ММ.ГГГГ» лучше «Ошибка». Нельзя показывать внутренний стек исключения пользователю. Ошибка должна быть видима и доступна с клавиатуры; один красный цвет недостаточен.

Культура влияет на десятичный разделитель и дату. Если формат вводит пользователь, нужно либо использовать текущую культуру, либо явно сообщить формат. Для машинного JSON применяют стандартизованное представление и сериализатор.

Проверка на клиенте улучшает опыт, но сервер обязан проверять повторно. Для WPF объект тоже должен защищать свои инварианты, потому что данные могут прийти не из поля, а из файла.

## Связь с практикой

ПР 8–10 требуют не добавлять недопустимый объект, показать понятную ошибку и проверить граничные случаи.
