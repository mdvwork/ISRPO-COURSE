# 19 CRUD, привязка полей и проверка данных

**Связь с программой:** тема 2.2, строка 9, 2 часа. Подготовка к ПР 12.2 и 13.

**Цель:** организовать полный цикл чтения и изменения данных без потери целостности.

**Результат:** студент описывает Create, Read, Update, Delete, границу транзакции и проверки каждого шага.

**Нужно знать:** WPF-привязка, команды, EF Core, ограничения БД. **Обязательная часть:** CRUD, редактируемая копия, валидация, сохранение, обработка ошибок. **Дополнительно:** оптимистическая конкуренция.

## Лекция

CRUD — четыре наблюдаемые операции: создать запись, прочитать, изменить и удалить. Интерфейс не считается рабочим, если изменённая строка видна только до перезапуска. Проверка включает повторное чтение из базы.

Для редактирования полезна отдельная форма или копия объекта. Пользователь может отменить ввод, не испортив выбранную строку. После проверки данные переносят в сущность и сохраняют.

```csharp
var project = new Project { Name = name.Trim(), Hours = hours };
db.Projects.Add(project);
await db.SaveChangesAsync();
```

У метода есть входы (`name`, `hours`, контекст), результат (новая строка с ключом) и отказ. До обращения к БД проверяют пустое имя и диапазон часов. База повторно защищает уникальность, обязательность и связи. Исключение перехватывают на границе интерфейса, записывают технические сведения в журнал, а пользователю дают понятное сообщение.

При обновлении сначала находят запись по ключу. Если её уже удалил другой процесс, интерфейс должен сообщить, что данные устарели. При удалении заранее определяют судьбу связанных задач: запрет, каскад или явное удаление. В учебном проекте используется запрет удаления проекта с задачами либо подтверждённое явное удаление — выбранное правило фиксируется.

Привязка полей обычно двусторонняя. `UpdateSourceTrigger=PropertyChanged` даёт раннюю обратную связь, но может запускать проверку на каждый символ. `LostFocus` проверяет позже. Выбор зависит от цены проверки и ожидаемого поведения.

Негативные сценарии обязательны: пустое имя, число вне диапазона, повтор уникального значения, удаление без выбора, повреждённый файл, заблокированная БД. Они не являются «нештатными мелочами»: именно они показывают надёжность инструмента.

Инспектирование кода дополняет запуск. Замечание должно назвать место, риск и исправление: «В обработчике `Delete_Click` удаляется по индексу; после сортировки удалится другой объект; передавайте `SelectedProject.Id`».
