**Обязательная часть:** решение и проект, форма, элементы, свойства, события `Load` и `Click`, запуск. **Дополнительно:** отделение логики от обработчика.

## Лекция

Visual Studio организует работу вокруг **решения** и **проектов**. Решение может содержать приложение, библиотеку и тесты. Проект определяет исходные файлы, целевую платформу, зависимости и правила сборки. Обозреватель решений показывает эту структуру; редактор изменяет код; список ошибок и окно вывода показывают диагностику; отладчик наблюдает выполнение.

В событийном приложении программа не выполняет один длинный сценарий сверху вниз. После запуска создаётся окно, затем цикл сообщений ждёт действий. Загрузка формы, нажатие кнопки, изменение выбора — события. Обработчик — метод, который подписан на событие и выполняется при его возникновении.

У элемента управления есть свойства: текст, размер, цвет, доступность, положение. Часть задаётся до запуска в файле формы или дизайнере, часть меняется программно. Изменение свойства — наблюдаемый результат, например после `Click` текст метки становится «Сохранено».

Обработчик `Load` подходит для начальной подготовки окна: заполнить список, установить исходное состояние, получить данные. Обработчик `Click` должен делать только работу нажатия. Если весь расчёт записать внутрь `Click`, его трудно тестировать. Лучше вынести правило в отдельный метод и вызвать его из обработчика.

```csharp
private void SaveButton_Click(object? sender, EventArgs e)
{
    StatusLabel.Text = BuildStatus(ProjectNameTextBox.Text);
}

private static string BuildStatus(string name)
{
    return string.IsNullOrWhiteSpace(name)
        ? "Введите название"
        : $"Проект «{name.Trim()}» сохранён";
}
```

`sender` указывает объект, создавший событие, а `e` содержит данные события. Для обычного `Click` это `EventArgs`; другие события передают координаты мыши, выбранный элемент или клавишу. Нельзя без проверки считать, что `sender` всегда нужный тип.

Запуск без отладки проверяет обычное выполнение. Запуск с отладкой позволяет остановиться и наблюдать значения. Сборка перед запуском преобразует исходники; ошибка компиляции не даёт получить новую сборку. Предупреждение не всегда блокирует запуск, но требует осмысленного решения.

Типовые ошибки: обработчик не подписан; имя элемента изменено только в одном месте; элемент перекрыт; код изменяет не то свойство; исключение скрывается пустым `catch`; окно запуска не то. Проверка начинается с воспроизводимых шагов: запустить, выполнить одно действие, записать ожидаемое и фактическое.
