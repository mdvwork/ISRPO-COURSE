# 03 Классификации инструментального программного обеспечения

**Связь с программой:** тема 2.1, строка 3, 2 часа.

**Цель:** научиться выбирать инструмент по задаче, этапу и уровню автоматизации.

**Результат:** студент сравнивает инструменты по нескольким основаниям и обосновывает выбор.

**Нужно знать:** жизненный цикл разработки и назначение IDE.

**Обязательная часть:** классификация по типу, категории и уровню. **Дополнительно:** локальные, облачные и командные средства.

## Лекция

Классификация нужна не для запоминания длинного списка, а для выбора. Один инструмент можно поместить в несколько групп, потому что основания отвечают на разные вопросы.

**По типу выполняемой работы** выделяют средства анализа требований и моделирования, редакторы и IDE, компиляторы и сборочные системы, отладчики, средства тестирования, профилировщики, системы управления данными, генераторы документации и системы контроля версий. Visual Studio объединяет несколько типов, а MySQL специализируется на хранении и обработке данных.

**По категории жизненного цикла** условно говорят о верхних CASE-средствах для анализа и проектирования, нижних — для реализации и тестирования, и интегрированных средах, поддерживающих несколько стадий. Граница условна: современная IDE может читать модель данных, запускать тесты и работать с Git, но требования всё равно могут храниться отдельно.

**По уровню автоматизации** есть отдельный инструмент, набор согласованных инструментов и интегрированная среда. Текстовый редактор с командной строкой — набор, если разработчик сам организовал связи. IDE хранит конфигурацию проекта и связывает сборку, запуск и отладку. Полная интеграция удобнее новичку, но скрывает команды; поэтому в курсе команды и ожидаемые файлы тоже объясняются.

Дополнительные основания: локальное или облачное выполнение; один пользователь или команда; универсальная или предметная специализация; свободная или коммерческая лицензия; графическое или командное управление; работа с исходным кодом или готовым бинарным модулем.

Выбор начинается не с популярности. Нужно описать задачу, ограничения компьютера и ОС, формат входных данных, требуемый результат, совместимость с проектом, поддержку версии и способ проверки. Для WPF необходим Windows-инструмент и .NET Desktop. Для HTML достаточно редактора и браузера. Для повторяемой сборки React нужен Node.js и менеджер пакетов. Для PHP с MySQL — локальный сервер и драйвер PDO.

Типичная ошибка — выбирать тяжёлую среду для простой задачи или менять инструмент посреди работы без фиксации версии. Другая ошибка — считать два инструмента эквивалентными только потому, что оба «делают сайты». CMS собирает сайт из готовой модели содержимого, а React строит интерфейс из компонентов; результаты и необходимые знания различаются.

## Упражнение 10 минут

Сравните три набора для задачи «показать 20 проектов из JSON и фильтровать их по статусу»: а) редактор + браузер; б) Visual Studio + WPF; в) React + Vite. Заполните строки «вход», «результат», «установка», «сильная сторона», «ограничение». Выберите вариант для старого компьютера и вариант для настольного Windows-приложения.

Проверяемый результат: выбор опирается минимум на два ограничения. Ответы: [ключ 03](../../teacher/EXERCISE_KEYS.md#03).
