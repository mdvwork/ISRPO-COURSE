# 08 Отладка программ

**Связь с программой:** тема 2.1, строка 8, 2 часа. Подготовка к ПР 4 и ПК 2.3.

**Цель:** освоить управляемый поиск причины ошибки вместо случайного изменения кода.

**Результат:** студент воспроизводит дефект, ставит точку останова, наблюдает состояние, формулирует причину и проверяет исправление.

**Нужно знать:** переменная, условие, обработчик.

**Обязательная часть:** дефект, воспроизведение, breakpoint, шаги, локальные переменные, стек, исключения. **Дополнительно:** условная точка останова.

## Лекция

Ошибка — несоответствие наблюдаемого результата требованию. Отладка — процесс поиска причины этого несоответствия. Она начинается не с точки останова, а с воспроизводимого сценария: начальные данные, действия, ожидаемый и фактический результат.

Ошибки бывают синтаксическими и сборочными, ошибками выполнения и логическими. Первые обнаруживает компилятор. Исключение сообщает, что операция не может продолжиться. Логическая ошибка даёт правдоподобный, но неверный результат и часто требует контрольного примера.

Точка останова останавливает выполнение перед строкой. На остановке разработчик смотрит значения переменных, выражения и стек вызовов. **Step Over** выполняет текущую строку без входа в вызываемый метод; **Step Into** входит в него; **Step Out** завершает текущий метод. Стек отвечает, откуда пришёл вызов.

Правильная стратегия: сузить область поиска. Сначала подтвердить входные данные, затем результат преобразования, условие выбора ветви и итоговое изменение состояния. Если значение стало неверным после определённой строки, причина рядом или в вызванном методе.

```csharp
decimal CalculateCost(int hours, decimal rate)
{
    return hours + rate; // воспроизводимая логическая ошибка
}
```

Для `hours = 2`, `rate = 500` ожидается `1000`, фактически `502`. На точке перед `return` оба входа правильны, значит ошибка в операторе. Исправление на умножение проверяют старым сценарием и дополнительными границами: 0 часов, 1 час, большое значение.

Исключение нельзя «исправлять» пустым `catch`. Оно скрывает причину. Перехватывают конкретное исключение там, где можно восстановиться или показать понятное сообщение, при этом техническая информация сохраняется в журнале. Для обычного неверного ввода лучше предварительная проверка.

Условная точка останова полезна, когда ошибка возникает на определённой итерации, например `project.Id == 17`. Логирование помогает, если остановка меняет время выполнения или дефект возникает вне IDE. Отладчик и журнал дополняют, а не заменяют тесты.
