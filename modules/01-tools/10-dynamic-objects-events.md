# 10 Динамические объекты область видимости и данные события

**Связь с программой:** тема 2.1, строка 10, 2 часа. Подготовка к ПР 5.

**Цель:** безопасно создавать объекты во время выполнения и понимать время их жизни.

**Результат:** студент объясняет область видимости, проверяет тип через `is`, использует безопасное приведение и данные события.

**Нужно знать:** объект, класс, событие, обработчик.

**Обязательная часть:** `new`, коллекция, область видимости, `is`, `as`, `sender`, `EventArgs`. **Дополнительно:** отписка от события.

## Лекция

Динамическое создание означает, что количество объектов определяется во время работы программы. Пользователь нажимает «Добавить поле», приложение создаёт новый `TextBox`, задаёт свойства, подписывает событие и помещает элемент в контейнер.

```csharp
private void AddButton_Click(object? sender, EventArgs e)
{
    var itemButton = new Button
    {
        Text = $"Проект {_buttons.Count + 1}",
        AutoSize = true
    };

    itemButton.Click += DynamicButton_Click;
    _buttons.Add(itemButton);
    ProjectsPanel.Controls.Add(itemButton);
}
```

Локальная переменная `itemButton` видна только внутри метода, но объект продолжает существовать, потому что на него ссылаются коллекция и контейнер. Поле `_buttons` доступно всем методам экземпляра формы. Область видимости имени и время жизни объекта связаны, но не одинаковы.

Один обработчик может обслуживать много элементов. Тогда `sender` нужно проверить:

```csharp
private void DynamicButton_Click(object? sender, EventArgs e)
{
    if (sender is not Button button)
    {
        return;
    }

    StatusLabel.Text = $"Выбран: {button.Text}";
}
```

Оператор `is` проверяет совместимость и может сразу создать переменную нужного типа. `as` возвращает ссылку нужного типа или `null`; после него нужна проверка. Прямое приведение бросает исключение при несовместимом типе. Для значимых типов и шаблонов поведение отличается, поэтому нельзя механически заменять операторы.

Данные события находятся в `e`. У мыши есть кнопка и координаты, у клавиатуры — клавиша, у изменения коллекции — добавленные и удалённые элементы. Использование конкретного типа `EventArgs` делает обработчик осмысленным.

При удалении динамического элемента нужно убрать его из визуального контейнера и собственной коллекции. Для долгоживущего издателя событий может потребоваться отписка, иначе ссылка через событие удержит объект. В простом окне жизненный цикл часто совпадает, но правило нужно знать.

Типовые ошибки: создать элемент и не добавить его в контейнер; подписать обработчик несколько раз; обращаться к `sender` без проверки; хранить объект только в локальной переменной, когда позже нужен доступ; удалять с экрана, но оставлять в коллекции; создавать без ограничений тысячи элементов.
