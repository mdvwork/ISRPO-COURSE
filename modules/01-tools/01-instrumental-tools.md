# 01 Инструментальные средства и виды программного обеспечения

**Связь с программой:** тема 2.1, строка 1, 2 часа. Подготовка к ПР 1.

**Цель:** понять, чем инструмент разработчика отличается от программы для конечного пользователя и какую часть работы он выполняет.

**Результат:** студент классифицирует программное средство по назначению, называет его вход, действие и результат, объясняет состав программного продукта.

**Нужно знать:** файл, папка, программа, операционная система.

**Обязательная часть:** определения, цепочка разработки, общее и специальное ПО. **Дополнительно:** лицензии и облачные среды.

## Лекция

Программное обеспечение — программы, данные и сопроводительные материалы, с которыми работает вычислительная система. Пользователь видит редактор, браузер или информационную систему. Разработчику, кроме будущей программы, нужны средства для создания, проверки и сопровождения: редактор кода, компилятор, отладчик, система контроля версий, средство моделирования, тестовый инструмент. Такие программы называют **инструментальными средствами разработки**.

У инструмента всегда есть вход и наблюдаемый результат. Редактор получает текст и сохраняет файл. Компилятор получает исходный код и выдаёт сборку либо список ошибок. Отладчик получает выполняемую программу и команды разработчика, позволяет остановиться на строке и увидеть состояние. Тестовый фреймворк получает тесты и код, а выдаёт протокол прохождения. Если неизвестно, что инструмент принимает и что должен выдать, проверить работу невозможно.

Разработка проходит не одной кнопкой, а цепочкой: задача → требования → модель → исходный код → сборка → запуск → проверка → исправление → версия результата. Инструмент поддерживает одно или несколько звеньев. IDE объединяет редактор, управление проектом, сборку, запуск, подсказки и отладку, но не определяет требования и не доказывает правильность программы автоматически.

В курсе различаются два основания классификации. По широкой роли выделяют системное ПО, прикладное ПО и инструментальное ПО. Операционная система управляет ресурсами компьютера; прикладная программа решает задачу пользователя; инструментальное средство помогает создавать и исследовать программы. По охвату задач говорят об общем и специальном ПО. Текстовый редактор общего назначения подходит разным пользователям; специализированный редактор схем или среда для конкретной платформы решает более узкую задачу. Это не взаимоисключающие шкалы: Visual Studio — инструментальное и одновременно специализированное ПО.

Программный продукт шире исполняемого файла. В него входят код, данные, настройки, зависимости, документация, тесты и сведения о версиях. Например, приложение-каталог без файла данных может запускаться, но не выполнять назначение. Проект без инструкции сборки трудно проверить на другом компьютере. Поэтому в лабораторных оценивается не снимок экрана, а воспроизводимый результат.

Инструменты имеют ограничения. Подсветка синтаксиса не гарантирует правильную логику. Успешная сборка не означает, что все сценарии работают. Генератор кода ускоряет типовые операции, но результат всё равно нужно читать и тестировать. Версия инструмента влияет на формат проекта и доступные функции. Отсюда правило курса: фиксировать среду, проверять ожидаемый результат и сохранять исходники.

## Пример

Нужно сделать каталог учебных проектов. Редактор используется для кода, компилятор — для проверки синтаксиса и получения программы, отладчик — для поиска причины неверного фильтра, Git — для сохранения версии, тестовый фреймворк — для повторяемой проверки сортировки. Ни один инструмент отдельно не заменяет постановку задачи.
