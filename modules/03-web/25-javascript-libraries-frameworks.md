# 25 JavaScript-библиотеки и фреймворки

**Связь с программой:** тема 2.3, строка 6, 2 часа. Подготовка к ПР 21.

**Цель:** осознанно выбрать уровень инструмента и понять компонентную модель React.

**Результат:** студент различает библиотеку и фреймворк, описывает компонент, props, state и эффект загрузки.

**Нужно знать:** функции, массивы, DOM, HTTP. **Обязательная часть:** назначение библиотек/фреймворков, компоненты React 19, Vite 8. **Дополнительно:** экосистема пакетов.

## Лекция

Библиотека предоставляет функции, которые вызывает приложение. Фреймворк задаёт структуру и сам вызывает пользовательский код в определённых точках. В реальной экосистеме граница не абсолютна: React официально называется библиотекой пользовательских интерфейсов, но обычно применяется с набором инструментов и соглашений.

Инструмент нужен, когда сложность состояния, повторение компонентов и командная работа оправдывают его стоимость. Для одной статической страницы React избыточен. ПР 14–20 намеренно показывают базовые технологии до React.

Компонент React — функция, которая по props и текущему state описывает интерфейс. Props приходят снаружи, state принадлежит экземпляру компонента. Состояние меняют через setter, а не прямой записью.

```jsx
function ProjectCard({ project }) {
  return (
    <article>
      <h2>{project.name}</h2>
      <p>{project.hours} ч.</p>
    </article>
  );
}
```

Список компонентов получает стабильный `key`, обычно идентификатор из данных. Индекс ломает сопоставление при сортировке или удалении. Получение данных — побочный эффект: интерфейс должен различать загрузку, успех, пустой набор и ошибку.

Vite создаёт dev-сервер и production-сборку. Node.js выполняет инструменты сборки, но браузер исполняет итоговый клиентский JavaScript. `package.json` фиксирует прямые зависимости и команды; lock-файл фиксирует точные разрешённые версии и должен быть в репозитории после установки.

Риск цепочки поставки реален: устанавливают только нужные пакеты, читают официальный источник, не копируют случайные команды, не публикуют секреты в `.env`. Клиентская переменная окружения не является секретом, если попадает в сборку.

Ошибки: использовать effect для вычисления, которое можно сделать при рендере; изменять state напрямую; применять индекс как key; игнорировать cleanup; считать dev-сервер готовым production-сервером; добавлять библиотеку ради одной функции.
