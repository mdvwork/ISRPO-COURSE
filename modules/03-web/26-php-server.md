# 26 Серверная обработка и основы PHP

**Связь с программой:** тема 2.3, строка 7, 2 часа. Подготовка к ПР 19–20.

**Цель:** понять жизненный цикл серверного запроса и написать проверяемую обработку PHP.

**Результат:** студент читает вход, проверяет его, вызывает функцию и формирует безопасный ответ.

**Нужно знать:** HTTP и HTML-формы. **Обязательная часть:** типы, условия, циклы, массивы, функции, superglobals, ответ. **Дополнительно:** строгие типы.

## Лекция

PHP-код выполняется на сервере для каждого запроса. Браузер получает результат, но не исходный PHP. Вход приходит из `$_GET`, `$_POST`, тела запроса, cookie и session — всё это недоверенные данные.

```php
<?php
declare(strict_types=1);

function normalizeName(string $value): string
{
    return trim($value);
}

$name = normalizeName((string)($_POST['name'] ?? ''));
if ($name === '') {
    http_response_code(422);
    exit('Укажите название');
}

echo htmlspecialchars($name, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
```

PHP имеет строки, целые и вещественные числа, логические значения, массивы, объекты и `null`. Ассоциативный массив хранит пары ключ–значение. `foreach` перебирает коллекцию. Функция уменьшает повторение и позволяет тестировать правило отдельно.

Проверка входа и экранирование выхода решают разные задачи. Валидация решает, допустимо ли значение; `htmlspecialchars` не позволяет допустимому тексту стать HTML-кодом при выводе. Для SQL нужен подготовленный запрос, а не HTML-экранирование.

Код ответа должен соответствовать результату. Ошибка ввода — `400` или `422`, отсутствие ресурса — `404`, непредвиденная ошибка сервера — `500`. Пользователю не показывают стек и пароль подключения. Подробности пишут в серверный журнал.

В учебной среде используется Open Server Panel на Windows. Корень сайта и адрес проекта определяются конфигурацией модуля; нельзя открывать PHP как локальный `file:///...`, потому что тогда интерпретатор не запускается.

Ошибки: доверять `$_POST`; использовать слабое сравнение без понимания преобразований; смешивать SQL, HTML и проверку в одном длинном файле; отправлять заголовок после вывода; хранить пароль БД в публичном репозитории; включать показ ошибок на production.
