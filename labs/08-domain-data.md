# ПР 8. Манипулирование данными предметной области

**Программа:** «Манипулирование данными предметной области», 2 часа. **Цель:** реализовать добавление, поиск и сортировку коллекции с проверкой. **Результат:** операции меняют модель, а представление синхронно отражает результат.

**Знания:** коллекции, модели, привязка, валидация. **ПО:** Windows 11, Visual Studio 2026, .NET 10/WPF. **Старт:** [wpf-projects](../starter/wpf-projects/README.md) или результат ПР 7.

## Выполнение

1. Проверьте добавление стартовой командой: имя короче трёх символов отключает кнопку; корректное добавляет объект. Запишите вход, изменение коллекции, визуальный результат.
2. Добавьте поле часов и проверку диапазона 0–1000. Команда доступна только при корректных имени и часах; метод `Add` повторяет проверку.
3. Создайте `ICollectionView` поверх `Projects`. Добавьте строку поиска и фильтр по имени. Исходная коллекция не уменьшается; меняется только вид.
4. Добавьте сортировку по названию. Проверьте, что удаление после сортировки удаляет `SelectedProject`, а не исходный/видимый индекс.
5. Покажите счётчик `Показано X из Y`. Проверьте пустой запрос, найденное и ненайденное значение.

## Самостоятельная часть

Добавьте комбинированный фильтр по статусу и максимальному числу часов. Вариант должен работать вместе со строкой поиска и иметь кнопку сброса, не очищающую исходные данные.

## Проверка и диагностика

Проверьте дубликат имени, границы часов, сортировку перед удалением, ноль результатов и сброс. Если фильтр не обновляется — вызовите `Refresh` при изменении условия. Если пропали данные после сброса — вы удаляли из коллекции вместо фильтрации view. Если команда остаётся активной — вызовите `RaiseCanExecuteChanged`.

## Сдача и критерии

Сдайте проект и таблицу минимум восьми сценариев. Критерии: 3 — добавление/валидация; 2 — поиск/сортировка; 3 — самостоятельный комбинированный фильтр; 2 — негативные случаи. **Критические ошибки:** фильтр разрушает исходные данные; удаление работает по индексу; недопустимый объект добавляется.
