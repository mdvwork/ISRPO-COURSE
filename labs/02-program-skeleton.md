# ПР 2. Каркас WinForms-программы

**Программа:** «Создание каркаса программы», 2 часа. **Цель:** проследить запуск приложения и обработку события. **Результат:** форма открывается, кнопка вызывает обработчик, состояние показывается пользователю.

**Знания:** проект, сборка, класс, метод. **ПО:** Windows 11, Visual Studio 2026, .NET 10, `.NET desktop development`.

## Старт и установка

Скопируйте [starter/winforms-tools](../starter/winforms-tools/README.md) в `Lab02`. Откройте `Course.WinForms.csproj`, восстановите зависимости и запустите. Ожидается исходное окно. Если предыдущая работа пропущена, этот набор полностью восстанавливает старт.

## Выполнение

1. В `Program.cs` найдите `Main`, `[STAThread]` и `Application.Run`. Подпишите комментариями: точка входа, настройка UI-потока, создание главной формы. Соберите — поведение не должно измениться.
2. В `MainForm` проследите поля, конструктор и `AddProject`. Поставьте точку останова на первой строке конструктора, нажмите `F5`, затем продолжите. Ожидается один вызов до показа формы.
3. Добавьте поле `Label _counter` со стартовым текстом `Добавлено: 0`, разместите внизу. Введите отдельное поле-счётчик и увеличивайте его только после успешного добавления.
4. Нажмите «Добавить» с пустым названием. Ожидается сообщение об ошибке, счётчик не меняется. Введите `Каталог`, нажмите снова: строка и счётчик появляются.
5. Закройте окно и проверьте остановку процесса в Visual Studio. Запишите цепочку `Main → MainForm() → событие Click → AddProject`.

## Самостоятельная часть

Добавьте кнопку «Очистить сообщения». Она очищает только `_message`, не список и не счётчик. Сделайте собственный обработчик и подпишите, какое состояние меняется.

## Проверка и диагностика

Проведите три сценария: пустой ввод; корректный ввод; очистка сообщения после добавления. Если элемент не виден — проверьте порядок `Controls.Add` и `Dock`. Если обработчик не вызывается — проверьте подписку `button.Click += ...`. Если приложение остаётся запущенным — найдите второе открытое окно/процесс.

## Сдача и критерии

Сдайте исходники, таблицу трёх сценариев и схему вызовов. Критерии: 3 — корректный жизненный цикл; 3 — счётчик меняется только при успехе; 2 — самостоятельная кнопка; 2 — объяснение. **Критические ошибки:** окно не запускается; кнопка не вызывает код; самостоятельная часть стирает данные вместо сообщения.
