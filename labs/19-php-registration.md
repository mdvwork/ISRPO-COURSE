# ПР 19.1. Регистрация пользователя PHP

**Программа:** ПР 19, часть «регистрация», 2 часа. **Цель:** принять форму, проверить ввод и сохранить только хеш пароля. **Результат:** пользователь создаётся подготовленным запросом, дубликат/ошибка обрабатываются без утечки данных.

**Знания:** PHP, POST, PDO, схема users. **ПО:** Windows 11, Open Server Panel 6.5.1, PHP 8.5, MySQL 8.4. **Старт:** [php-site](../starter/php-site/README.md) после ПР 18.

## Стартовое состояние и восстановление

Создайте `config.local.php` по примеру; не сдавайте его. Если ПР 18 нет, выполните `schema.sql` и `seed.sql`. Стартовый `register.php` уже показывает безопасную последовательность; студент обязан проследить её и сделать самостоятельное изменение.

## Выполнение

1. Откройте `/health.php`; ожидается JSON ok. Затем `/register.php`; DevTools Network показывает GET 200.
2. Отправьте пустые/неверные значения. Клиентская проверка может остановить запрос; отключите её только в DevTools для проверки сервера. Сервер возвращает 422 и не создаёт строку.
3. Отправьте новый email и пароль 12+ символов. Ожидается INSERT через `prepare`, сообщение и строка в users. В БД `password_hash` не равен паролю и обычно начинается идентификатором алгоритма.
4. Повторите email. Ожидается 409/общее сообщение, а не SQL-текст. Техническая ошибка записывается сервером.
5. Проверьте скрытый CSRF token: изменение/отсутствие даёт 400. Объясните, почему токен сравнивают `hash_equals`.

## Самостоятельная часть

Добавьте обязательное отображаемое имя 2–80 символов. Измените schema и prepared INSERT. Имя хранится отдельно от email, выводится через `h`, а пустое/длинное значение отклоняется сервером.

## Проверка и диагностика

Сценарии: неверный email, короткий пароль, успех, дубликат, неверный CSRF, HTML в имени. Если «could not find driver» — включите PDO MySQL для выбранной PHP-версии. Если headers already sent — уберите вывод до session/header. Не включайте пароль в журнал/отчёт.

## Сдача и критерии

Сдайте исходники, миграцию/схему и обезличенную таблицу результатов. Критерии: 3 — проверка/хеш; 2 — prepared/ошибки; 3 — самостоятельное имя; 2 — CSRF/негативные сценарии. **Критические ошибки:** пароль хранится открыто/обычным SHA; SQL строится конкатенацией; config с паролем сдан; сервер доверяет только HTML required.
