# ПР 3. Выбор с RadioButton

**Программа:** «Работа с переключателями RadioButton», 2 часа. **Цель:** реализовать взаимоисключающий выбор и проверить состояние. **Результат:** проект получает ровно один статус из группы.

**Знания:** событие, условие, свойства элемента. **ПО:** Windows 11, Visual Studio 2026, .NET 10. **Старт:** свежая копия [winforms-tools](../starter/winforms-tools/README.md) либо результат ПР 2.

## Выполнение

1. Запустите исходный проект. Проверьте, что `_planned` выбран, а `_active` — нет. Ожидается одна активная кнопка в общем контейнере.
2. Добавьте третий `RadioButton` со значением «Завершён». Разместите его в том же `FlowLayoutPanel`; иначе он образует отдельную группу.
3. Вынесите чтение статуса в метод:

   ```csharp
   private string GetSelectedStatus() =>
       _active.Checked ? "В работе" :
       _done.Checked ? "Завершён" : "Запланирован";
   ```

   Подставьте результат при создании `ProjectItem`.
4. Добавьте обработчик `CheckedChanged`, который показывает выбранный статус в `_message`, но реагирует только когда `Checked == true`. Проверьте три выбора: одно событие снятия не должно затирать итог.
5. Составьте таблицу состояний трёх булевых свойств и отметьте допустимые строки. В интерфейсе допустимы только три строки, где истинно ровно одно значение.

## Самостоятельная часть

Создайте вторую независимую группу «Приоритет»: низкий/обычный/высокий. Сохраните приоритет в расширенной модели и покажите в строке. Выбор статуса не должен снимать приоритет.

## Проверка и диагностика

Добавьте по одному проекту каждого статуса и двух разных приоритетов. Если можно выбрать два статуса — элементы находятся в разных контейнерах. Если выбор статуса снимает приоритет — обе группы в одном контейнере без отдельных `GroupBox`/панелей. Если отображается прежнее значение — статус вычисляется до клика или сохранён отдельно без обновления.

## Сдача и критерии

Сдайте проект, таблицу состояний и шесть проверок. Критерии: 3 — статус взаимоисключающий; 2 — корректная модель; 3 — независимый приоритет; 2 — тесты/объяснение. **Критические ошибки:** возможно ноль или несколько статусов при сохранении; показанное значение не совпадает с моделью; нет самостоятельной группы.
