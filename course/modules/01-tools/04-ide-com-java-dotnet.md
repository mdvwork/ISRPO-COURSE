# 04 IDE COM Java и платформы NET

**Связь с программой:** тема 2.1, строка 4, 2 часа.

**Цель:** различить среду разработки, компонентную модель и среду выполнения.

**Результат:** студент объясняет роли IDE, COM, JVM, .NET Framework и современного .NET и не смешивает их.

**Нужно знать:** исходный код, библиотека, операционная система.

**Обязательная часть:** IDE, COM, Java/JVM, CLR, .NET Framework. **Дополнительно:** современный .NET и совместимость.

## Лекция

IDE — программа для разработки. Платформа выполнения — среда и библиотеки, необходимые готовой программе. Компонентная модель — правила взаимодействия частей. Эти понятия могут встречаться вместе, но отвечают на разные вопросы.

Современная IDE хранит решение и проекты, запускает компилятор, показывает диагностику, управляет зависимостями, запускает приложение и подключает отладчик. Она не является языком и не становится частью результата автоматически. Один язык можно использовать в разных IDE, а IDE может поддерживать несколько языков.

COM, Component Object Model, определяет двоичные интерфейсы Windows-компонентов. Клиент обращается к интерфейсу, не зная внутреннего языка реализации. Важны идентификаторы, контракты интерфейсов и управление временем жизни. COM лежит в основе ряда исторических Windows-технологий и до сих пор встречается при интеграции с системными и офисными компонентами. В новых C++-проектах Microsoft рекомендует безопасные обёртки вместо ручного управления ссылками. В курсе COM изучается концептуально, без регистрации собственного компонента.

Java компилируется в байткод, который выполняет JVM. JVM отвечает за загрузку классов, проверку, выполнение и управление памятью. Библиотеки Java и конкретный JDK дополняют среду. На дату выпуска Java 25 — LTS, но практические этого курса не требуют установки JDK; Java нужна для сравнения подходов и исторического контекста CASE.

.NET Framework — Windows-компонент для классических приложений; актуальная последняя версия 4.8.1 поддерживается вместе с Windows. Современный .NET — отдельная кроссплатформенная линия. В .NET исходный C# обычно компилируется в промежуточный язык, а CLR загружает сборки, выполняет код, управляет памятью и исключениями. WPF при этом остаётся Windows-технологией даже на современном .NET.

В этом выпуске практические проекты используют .NET 10 LTS и `net10.0-windows`. Это современная реализация, а не переименование .NET Framework. Если выбрать шаблон `WPF Application (.NET Framework)`, проект получит другой формат целевой платформы и набор зависимостей. Смешивание пакетов .NET 10 и .NET Framework без анализа приводит к ошибкам совместимости.

Компонентная идея общая: часть предоставляет контракт, а другая его использует. Но двоичный интерфейс COM, Java-байткод и .NET-сборка не взаимозаменяемы. Для интеграции нужен предусмотренный мост: межпроцессный протокол, вызов API, COM-interop или другой адаптер.

## Авторская схема

```text
задача разработчика -> IDE -> компилятор -> сборка
                                      -> среда выполнения -> работа программы
компонент A -> контракт/интерфейс -> компонент B
```

Схема учебная, не иллюстрация официальной документации.
