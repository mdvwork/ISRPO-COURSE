# 28 MVC, PHP-фреймворки и CMS

**Связь с программой:** тема 2.3, строка 9, 2 часа. Подготовка к ПР 20 и 22.

**Цель:** разделить ответственность в приложении и выбрать между собственным кодом, фреймворком и CMS.

**Результат:** студент распределяет задачи между Model, View и Controller и обосновывает выбор CMS.

**Нужно знать:** HTTP, PHP, БД, шаблоны. **Обязательная часть:** MVC, маршрутизация, шаблон, фреймворк, CMS, WordPress. **Дополнительно:** жизненный цикл запроса.

## Лекция

MVC разделяет ответственность. Model хранит правила и работу с данными. Controller принимает запрос, проверяет разрешение и выбирает действие. View формирует представление. MVC не означает три обязательных файла; важна граница ответственности.

```text
HTTP-запрос → маршрут → Controller → Model/хранилище
                              ↓
                         View → HTTP-ответ
```

В простом PHP-проекте `projects.php` может играть роль controller, функция репозитория — model, а подключаемый шаблон — view. SQL не должен находиться внутри HTML-цикла, а шаблон не должен решать права доступа.

Фреймворк предоставляет маршрутизацию, контейнер зависимостей, шаблоны, миграции и соглашения. Он ускоряет типовые задачи, но требует изучения и обновлений. В учебной работе MVC разбирается на малом собственном примере; конкретный большой PHP-фреймворк не вводится вместо основ программы.

CMS управляет содержимым через административный интерфейс. WordPress хранит записи, страницы, меню, пользователей, темы и плагины. Это не конструктор без кода: администратор отвечает за обновления, резервные копии, права, темы и плагины.

Выбор:

- статический HTML — небольшое редко меняющееся содержание;
- собственное приложение — специфические правила и процессы;
- фреймворк — сложное приложение с разработкой;
- CMS — типовые публикации и управление содержимым редакторами.

Плагин получает кодовые права сайта, поэтому устанавливают только необходимое из проверенного источника. Перед обновлением делают резервную копию и проверяют совместимость. Локальный учебный WordPress не публикуют в Интернет без отдельной настройки HTTPS, резервирования и обновлений.

Ошибки: controller с тысячей строк; модель печатает HTML; view строит SQL; хранить изменение ядра CMS; ставить много плагинов «на будущее»; считать локальную установку защищённым публичным сайтом; не экспортировать содержимое перед переносом.
