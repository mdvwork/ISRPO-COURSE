# 20 Интернет, DNS, WWW, HTTP и защита соединения

**Связь с программой:** тема 2.3, строка 1, 2 часа. Подготовка ко всему веб-блоку.

**Цель:** проследить путь запроса от адреса до ответа и определить границы защиты HTTPS.

**Результат:** студент разбирает URL, HTTP-запрос/ответ, коды состояния и отличает шифрование канала от безопасности приложения.

**Нужно знать:** клиент, сервер, файл. **Обязательная часть:** TCP/IP как основа, DNS, URL, HTTP-методы, статусы, заголовки, HTTPS. **Дополнительно:** кэширование.

## Лекция

Интернет — сеть сетей, а WWW — один из сервисов поверх неё. Браузер-клиент получает адрес, DNS сопоставляет доменное имя с IP-адресом, затем устанавливается соединение и передаётся HTTP-запрос. Сервер возвращает статус, заголовки и при необходимости тело ответа.

URL `https://example.test/projects?status=open` содержит схему `https`, узел `example.test`, путь `/projects` и строку запроса. Пароль нельзя помещать в URL: адрес попадает в историю и журналы.

```http
GET /api/projects/7 HTTP/1.1
Host: example.test
Accept: application/json

HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"id":7,"name":"Практикум"}
```

`GET` читает, `POST` обычно создаёт или запускает обработку, `PUT` заменяет, `PATCH` частично изменяет, `DELETE` удаляет. Метод описывает намерение, но сервер обязан проверять права. Статусы: `200` успех, `201` создано, `204` без тела, `400` неверный запрос, `401` не установлена личность, `403` недостаточно прав, `404` ресурс не найден, `500` ошибка сервера.

HTTPS — HTTP через TLS. Он шифрует канал, проверяет сертификат узла и защищает целостность передачи. Он не исправляет SQL-инъекцию, слабый пароль, XSS или ошибочные права. Сертификат с предупреждением нельзя «просто принять» в реальной системе.

Браузер применяет модель происхождения, cookies и политики содержимого. Сервер не доверяет входу: проверяет тип, длину, права и контекст, экранирует данные при выводе. Секреты не хранят в репозитории.

Типичные ошибки: считать WWW и Интернет синонимами; путать DNS с поиском; считать любой `200` корректным результатом; отправлять изменение через `GET`; передавать пароль в URL; думать, что HTTPS делает код безопасным.
