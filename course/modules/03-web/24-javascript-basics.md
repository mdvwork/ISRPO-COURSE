## Лекция

JavaScript выполняется в браузере и может читать DOM, реагировать на события и отправлять запросы. Данные приложения лучше хранить в объектах и массивах, а DOM считать представлением. Иначе состояние приходится угадывать по тексту элементов.

```js
const projects = [
  { id: 1, name: "Каталог", hours: 12, done: false },
  { id: 2, name: "Трекер", hours: 8, done: true }
];

function visibleProjects(items, query) {
  const normalized = query.trim().toLocaleLowerCase("ru-RU");
  return items.filter(item =>
    item.name.toLocaleLowerCase("ru-RU").includes(normalized)
  );
}
```

`const` запрещает переназначить переменную, но объект внутри всё ещё может меняться. `let` нужен для действительно меняемой ссылки. Необъявленные переменные и `var` усложняют область видимости.

Функция получает аргументы и возвращает результат. Чистую функцию вроде фильтра легко тестировать: одинаковый ввод даёт одинаковый вывод. Функция отрисовки отдельно создаёт элементы.

```js
button.addEventListener("click", () => {
  render(visibleProjects(projects, search.value));
});
```

Событие содержит данные о произошедшем; подписка отделяет HTML от поведения. Для пользовательского текста применяют `textContent`, а не `innerHTML`: так строка не становится разметкой. В обработчике формы вызывают `event.preventDefault()`, если отправка будет выполнена кодом.

Сравнивают строго `===`. Преобразование строки в число делают явно и проверяют `Number.isFinite`. Ошибки не скрывают пустым `catch`: показывают состояние и оставляют диагностическое сообщение для разработчика.

Ошибки: мутировать DOM в разных местах; создавать слушатель заново при каждой отрисовке; использовать индекс массива как устойчивый идентификатор; доверять HTML из ввода; путать асинхронный результат с готовым значением.
