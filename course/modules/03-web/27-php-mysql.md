## Лекция

MySQL хранит таблицы и обеспечивает ограничения. PHP обращается к серверу базы через драйвер. В курсе используется PDO: один интерфейс для подключения, подготовки и выполнения запросов.

```php
$pdo = new PDO($dsn, $user, $password, [
    PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION,
    PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
    PDO::ATTR_EMULATE_PREPARES => false,
]);

$stmt = $pdo->prepare(
    'SELECT id, email, password_hash FROM users WHERE email = :email'
);
$stmt->execute(['email' => $email]);
$user = $stmt->fetch();
```

Подготовленный запрос отделяет структуру SQL от значения. Конкатенация `"... WHERE email='$email'"` позволяет входу изменить запрос и недопустима. Параметр заменяет только значение, не имя таблицы или направление сортировки; такие части выбирают из заранее разрешённого списка.

Пароль не шифруют обратимо и не хранят открытым. При регистрации сохраняют `password_hash($password, PASSWORD_DEFAULT)`, при входе применяют `password_verify`. Поле хеша делают достаточно длинным, например `VARCHAR(255)`, потому что алгоритм и длина могут меняться.

После успешной аутентификации сервер создаёт сессию и меняет её идентификатор через `session_regenerate_id(true)`. Cookie сессии настраивают `HttpOnly`, `Secure` при HTTPS и подходящий `SameSite`. Выход уничтожает серверное состояние и cookie. Запросы, меняющие данные, защищают CSRF-токеном.

Транзакция объединяет несколько изменений: либо все применены, либо ни одно. Она нужна, например, при создании проекта и обязательной первой задачи. Не держат транзакцию открытой, пока пользователь заполняет форму.

Ошибки: пароль в БД открытым текстом; один общий хеш; MD5/SHA без специализированного алгоритма; SQL-конкатенация; сообщение «такой email есть» при входе, раскрывающее пользователей; сессия без регенерации; настройки БД в Git.
