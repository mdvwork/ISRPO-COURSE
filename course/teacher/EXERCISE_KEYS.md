# Ключи к аудиторным упражнениям

Каталог публичный: ключи предназначены для разбора после выполнения, а не для секретного контроля.

## 01

Инструмент определяется входом, действием и результатом. Редактор: текст → изменение → файл; компилятор: исходный код → проверка/трансляция → сборка или диагностика; отладчик: программа и состояние → управление выполнением → наблюдения. Общая ОС не заменяет специальный инструмент разработки.

## 02

CASE помогает моделировать, связывать требования и артефакты, генерировать часть результата и проверять согласованность. Он не принимает предметные решения за разработчика. Модель ценна, если поддерживается вместе с системой.

## 03

Редактор — создание исходника; компилятор — перевод/проверка; debugger — наблюдение исполнения; VCS — история изменений; ORM — отображение данных; тестовый runner — запуск проверок. Один IDE объединяет классы инструментов, но не делает их одной функцией.

## 04

COM — бинарная компонентная модель Windows, Java — байткод/JVM, .NET Framework — Windows-реализация .NET исторической ветки, современный .NET — кроссплатформенная поддерживаемая линия. Совпадает задача управляемого выполнения, но форматы и среды не взаимозаменяемы.

## 05

Для кнопки: событие Click, подписанный обработчик, проверка входа, изменение модели, уведомление/вывод. Свойство `Text` описывает состояние элемента; событие сообщает о действии. Без подписки метод сам не вызывается.

## 06

Вход — строки полей; преобразование — `TryParse`; правило — диапазон; результат — объект/вывод; отказ — понятное сообщение. Тип выбирается по смыслу: часы `int`, завершённость `bool`, имя `string`.

## 07

Для трёх RadioButton допустимы `100`, `010`, `001`; остальные комбинации нарушают «ровно один». Независимый приоритет должен быть в другой группе. `CheckBox` допускает независимые сочетания.

## 08

Минимальная карточка дефекта: ввод 3/4/5, ожидание 4, факт 6, место `Average`, наблюдение суммы 12 и делителя 2, причина неверный делитель, исправление 3, повторные границы. «Не работает» не воспроизводимо.

## 09

Класс задаёт состояние и поведение, объект — экземпляр. `record` удобен для значений и сравнения по данным, `struct` — небольшое value-значение, класс — сущность с идентичностью. Идентификатор не равен позиции в списке.

## 10

Обработчик динамической строки должен держать ссылку на конкретный объект/id. `is` одновременно проверяет и даёт переменную; `as` возвращает null при несовместимости. Удаление по видимому индексу опасно после фильтра/сортировки.

## 11

XAML образует дерево. `Grid` содержит дочерние элементы, вложенность задаёт владение и компоновку. Silverlight исторически близок синтаксисом XAML, но снят с поддержки и не назначается для установки; практика выполняется на WPF.

## 12

WPF использует retained-mode графику: разработчик описывает дерево, framework измеряет, размещает и рисует. DIP обеспечивает масштабирование. Векторный принцип не гарантирует хорошую доступность и не отменяет проверки шрифтов/масштаба.

## 13

`Grid` — строки/столбцы, `StackPanel` — последовательность, `DockPanel` — края и остаток. Style задаёт свойства повторно, ControlTemplate меняет визуальную структуру control, DataTemplate — представление данных.

## 14

Локальное routed event идёт от источника по дереву; dependency property участвует в binding/style/inheritance/animation. `DataContext` наследуется вниз. Binding error ищется в Output и точном пути свойства.

## 15

Название: `"Каталог"`/3 символа/пусто; часы 12/0 или 1000/-1; дата корректная/граница/неверный формат; статус известный/первый/неизвестный. Форматирование даты или bool в текст — преобразование; диапазон и обязательность — проверка.

## 16

«Список», «Новый проект», «О программе» — навигация. «Сохранить» доступно при корректных изменениях, «Удалить» — при выборе и праве; это команды. Меню, toolbar и shortcut могут ссылаться на одну команду.

## 17

Алгоритм: получить выбранный объект/id; проверить выбор/право; подтвердить; удалить по id из хранилища; после успеха обновить коллекцию/выбор; при отказе сохранить UI и показать сообщение. Индекс не используется.

## 18

Project 1—N Task. Если Task M—N Category, нужна `TaskCategory(task_id FK, category_id FK)` с составным PK либо отдельным id плюс UNIQUE пары. Кардинальность и правило удаления должны быть подписаны.

## 19

Матрица содержит для C/R/U/D как минимум успех и отказ. Например Create: валидный ввод → новая строка/id; пустое имя → 422/сообщение и без строки. Read отсутствующего id → 404. Update повторного имени → конфликт. Delete родителя с задачами → запрет/явное правило.

## 20

Схема `https`, узел `college.example`, путь `/courses/22`, query `part=2`. Получить — GET/200; создать — POST/201; удалить без права — DELETE/403; отсутствующий — GET/404.

## 21

Добавляются `label for`, уникальные id, `button type`, осмысленный или пустой alt. Поле без `name` участвует в UI, но не входит в данные успешной отправки формы.

## 22

Обычная модель: 300 + 2×20 + 2×2 = 344 px. `border-box`: внешняя заданная ширина 300 px. Имена вроде `.is-complete`, `.validation-message` описывают состояние/роль, не цвет.

## 23

`col-12 col-md-6 col-xl-4`: одна колонка около 360 px, две около 800 px, три около 1300 px. Фактические границы берутся из Bootstrap 5.3.8; проверяют также переполнение и порядок.

## 24

`"ка"` находит «Каталог», пробельный запрос после trim — все проекты, `"нет"` — пусто. `innerHTML=userText` допускает разметку; создать элемент и назначить `textContent`.

## 25

Массив ответа сервера — загруженные данные/state; поисковая строка — локальный state; отфильтрованный массив — вычисляемое значение; запрос API — внешний эффект. Props нужны, когда данные передаёт родитель.

## 26

`"  Каталог "` → `"Каталог"`, допустимо, вывод без изменения; `""` → пусто, 422; `<b>Тест</b>` может быть допустимым текстом, но выводится `&lt;b&gt;Тест&lt;/b&gt;`. Валидация и экранирование не взаимозаменяемы.

## 27

Проблемы: SQL-инъекция и открытый пароль. Последовательность: нормализовать email; prepared SELECT по email; получить hash; `password_verify`; одинаковая внешняя ошибка при отказе; `session_regenerate_id(true)` и user id при успехе.

## 28

Маршрут/id и выбор действия — Controller; загрузка и просрочка как предметное правило — Model; заголовок — View; проверка права обычно application/controller с сервисом policy. Визитка — static, редакционный типовой сайт — CMS, индивидуальные траектории — приложение/фреймворк; итог зависит от требований.
