# ПР 12.2. CRUD WPF через EF Core

**Программа:** ПР 12, часть 2, 2 часа. **Цель:** связать WPF-представление с устойчивым хранением. **Результат:** Create/Read/Update/Delete сохраняются в SQLite и подтверждаются новым запуском.

**Знания:** часть 12.1, WPF/MVVM, команды, async. **ПО:** Windows 11, Visual Studio 2026, .NET 10, EF Core 10.0.12.

## Стартовое состояние и восстановление

Продолжайте 12.1 и подключите проект данных к копии WPF-набора. Если 12.1 пропущена, запустите [EF-старт](../starter/ef-core/README.md) один раз, затем добавьте ссылку на него в WPF-проект. Резервную копию `course.db` храните до CRUD.

## Выполнение

1. Создайте сервис репозитория с методами чтения, добавления, изменения и удаления по `Id`. ViewModel не должна строить SQL.
2. При старте асинхронно загрузите проекты в `ObservableCollection`; покажите loading/error/empty/ready.
3. Добавление: проверьте DTO, сохраните в БД, затем добавьте возвращённую сущность в коллекцию. Ключ должен быть выдан БД.
4. Изменение: загрузите по id, примените проверенные поля, `SaveChangesAsync`, обновите отображаемый объект.
5. Удаление: запросите подтверждение на уровне View, передайте решение команде, удалите по id. При связанных задачах покажите запрет `RESTRICT`.
6. Закройте приложение, запустите снова и подтвердите все изменения чтением из базы.

## Самостоятельная часть

Реализуйте редактирование в отдельной копии/диалоге с «Сохранить» и «Отмена». Отмена не меняет ни объект списка, ни базу. Проверьте длинное имя и конкурентно удалённую запись.

## Проверка и диагностика

Для каждой CRUD-операции выполните успешный и ошибочный сценарий. Если UI обновился, а база нет — коллекция меняется до `SaveChanges`. Если дубликат ключа tracking — один контекст живёт слишком долго или сущность прикреплена дважды. Если окно зависает — используется `.Wait()`/`.Result`.

## Сдача и критерии

Сдайте проекты, тестовую БД и таблицу 8 сценариев. Критерии: 3 — полный CRUD; 2 — повторное чтение; 3 — самостоятельная отменяемая форма; 2 — ошибки/async. **Критические ошибки:** изменение теряется после запуска; удаляется по индексу; ошибка БД выдаётся за успех; отмена меняет данные.
