# ПР 19.2. Авторизация, сессия и выход PHP

**Программа:** ПР 19, часть «авторизация», 2 часа. **Цель:** проверить пароль и создать безопасное состояние входа. **Результат:** верная пара создаёт сессию, неверная даёт одинаковую ошибку, выход завершает сессию POST-запросом.

**Знания:** часть 19.1, `password_verify`, cookie/session. **ПО:** тот же PHP/MySQL. **Старт:** продолжение 19.1; если она пропущена, разверните [php-site](../starter/php-site/README.md) и создайте одного тестового пользователя через форму, не ручным открытым паролем в SQL.

## Выполнение

1. Откройте `login.php`. Проследите SELECT только по email и `password_verify` в PHP. Пароль не включён в SQL.
2. Введите существующий email и неверный пароль; затем несуществующий email. Оба ответа имеют одинаковый внешний текст и 401, чтобы не раскрывать наличие пользователя.
3. Введите верный пароль. До/после входа посмотрите имя session cookie: значение меняется из-за `session_regenerate_id(true)`, `$_SESSION['user_id']` установлен.
4. Создайте защищённую `account.php`: без user_id — redirect 303 на login; с user_id — запрос пользователя по параметру и безопасный вывод email/name.
5. Сделайте форму выхода POST с CSRF, вызывающую `logout.php`. После выхода прямой переход на account снова перенаправляет на login.

## Самостоятельная часть

Добавьте счётчик пяти неуспешных попыток в сессии с временной блокировкой на 60 секунд. Сообщение не раскрывает, какой email существует. Это учебная защита, не замена серверному rate-limit.

## Проверка и диагностика

Проверьте неизвестный email, неверный/верный пароль, прямой account, выход, поддельный CSRF, пять ошибок. Если сессия не сохраняется — проверьте cookie, адрес и вызов session_start до вывода. Если logout сделан GET — измените на POST. При локальном HTTP Secure cookie ожидаемо false; публично обязателен HTTPS.

## Сдача и критерии

Сдайте PHP, таблицу сценариев без паролей/cookie-значений. Критерии: 3 — проверка/сессия; 2 — защищённая страница/выход; 3 — самостоятельное ограничение; 2 — одинаковые ошибки/CSRF. **Критические ошибки:** пароль сравнивается строкой с хешем; session id не меняется; выход через GET; защита страницы только скрывает ссылку.
