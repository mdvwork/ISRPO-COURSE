# ПР 9. Манипулирование данными классов

**Программа:** «Манипулирование данными классов», 2 часа. **Цель:** безопасно применять полиморфизм и проверять типы. **Результат:** общая коллекция содержит разные типы задач, а операции не зависят от небезопасного приведения.

**Знания:** наследование, интерфейс, `is`, `as`, виртуальный метод. **ПО:** Windows 11, Visual Studio 2026, .NET 10. **Старт:** WPF-набор; создайте ветку/копию до изменения модели.

## Выполнение

1. Создайте базовый абстрактный `WorkItem` с `Id`, `Title` и абстрактным `GetSummary()`.
2. Добавьте `DevelopmentTask` с языком и `DocumentationTask` с количеством страниц. Переопределите `GetSummary`, не проверяя тип снаружи.
3. Создайте `ObservableCollection<WorkItem>` с двумя типами и покажите `GetSummary()` в DataGrid/списке. Ожидается свой текст для каждого объекта.
4. Добавьте действие, доступное только `DevelopmentTask`, через pattern matching: `if (Selected is DevelopmentTask task)`. Для другого типа покажите понятное состояние.
5. Сравните `as` и явное приведение на объекте неверного типа: `as` даёт `null`, явное приведение — исключение. Не оставляйте намеренное падение в итоговом UI.

## Самостоятельная часть

Добавьте третий тип `ReviewTask` с `FilePath` и `Severity`. Реализуйте его итоговую строку и отдельное условие: severity только 1–3. Представление должно принять новый тип без изменения существующих `GetSummary`.

## Проверка и диагностика

Проверьте по два объекта каждого типа, отсутствие выбора, неверную severity и действие на несовместимом типе. Если список знает все типы через длинную цепочку `if`, полиморфизм не использован. Если `as` результат разыменован без проверки — возможен `NullReferenceException`.

## Сдача и критерии

Сдайте классы, UI и таблицу сценариев. Критерии: 3 — полиморфная модель; 2 — безопасная типизация; 3 — самостоятельный тип/инвариант; 2 — проверка. **Критические ошибки:** необработанное неверное приведение; третий тип требует переписывать все существующие классы; ограничения не проверяются.
