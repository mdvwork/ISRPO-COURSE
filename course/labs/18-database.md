# ПР 18. База данных веб-приложения

**Программа:** «Создание базы данных», 2 часа. **Цель:** создать схему MySQL с ключами, ограничениями и воспроизводимой инициализацией. **Результат:** база содержит users/projects и начальные данные, неверные связи отклоняются.

**Знания:** ER-модель, SQL CREATE/INSERT/SELECT. **ПО:** Windows 11, Open Server Panel 6.5.1, MySQL 8.4 LTS (8.4.11). **Старт:** [php-site](../starter/php-site/README.md), файлы `database/schema.sql`, `seed.sql`.

## Установка и исходное состояние

Установите/запустите MySQL по [GETTING_STARTED](../GETTING_STARTED.md). Создавайте только учебную локальную БД. Если старт нарушен, удалите **только собственную** БД `isrpo_course` через панель после проверки имени и снова выполните schema/seed.

## Выполнение

1. Нарисуйте схему users 1 — N projects; `owner_id` допускает null, удаление пользователя устанавливает null. Подпишите PK, UNIQUE, FK, CHECK.
2. Выполните `schema.sql`. Проверьте `SHOW CREATE TABLE users;` и projects — движок принял ограничения.
3. Выполните `seed.sql`, затем `SELECT id,name,hours,status FROM projects ORDER BY name;`. Ожидаются три строки.
4. Повторите seed. Ожидается ошибка уникальности; это нормальная проверка, не повод удалить UNIQUE. Для воспроизводимости решите: чистая БД или idempotent seed, и зафиксируйте.
5. Попытайтесь вставить owner_id, которого нет. Ожидается ошибка FK. Вставьте часы 1001 — ошибка CHECK.

## Самостоятельная часть

Добавьте таблицу `project_tasks`: id, project_id, title, is_done, due_date nullable; внешний ключ и проверки. Добавьте по две задачи к двум проектам и запрос количества незавершённых задач по проекту с `GROUP BY`.

## Проверка и диагностика

Сохраните вывод `SHOW CREATE TABLE`, успешный SELECT и две ожидаемые ошибки. Если кириллица искажена — проверьте utf8mb4 на БД/соединении. Если FK не действует — проверьте InnoDB и точные типы столбцов. Не выполняйте DROP без проверки выбранной БД.

## Сдача и критерии

Сдайте SQL schema/seed/query и `db-report.md`, без реальных пользователей. Критерии: 3 — основная схема; 2 — воспроизводимость/ограничения; 3 — самостоятельные tasks/query; 2 — негативные проверки. **Критические ошибки:** пароли предусмотрены открытым текстом; нет PK/FK; запрос работает только после ручных необъяснённых действий.
